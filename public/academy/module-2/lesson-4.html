Errores Comunes al Introducir Datos (Y Cómo Evitarlos)

📖 8 min lectura 🎓 Módulo 2 - Lección 4

Los 7 errores más costosos

Error #1: Ignorar repositioning

El error

Dejar el campo "Repositioning" vacío cuando delivery es en zona muerta.

La realidad: Load en Laredo requiere 280 millas a San Antonio. RPM mostrado: $1.60/mi → RPM REAL: $1.25/mi. Diferencia: $0.35/mi de error = $448 de "ganancia fantasma".

La solución: Siempre pregúntate "¿Hay freight donde entrego?" Si NO → ingresar repositioning.

Error #2: Usar direcciones incompletas

El error

Ingresar solo "Chicago" (ciudad es enorme: 100+ millas).

La realidad: "Chicago" puede ser Downtown, O'Hare (15mi), Joliet (40mi), Aurora (45mi). Error potencial: 40-80 millas.

La solución: Malo: "Chicago" — Mejor: "Chicago, IL" — Best: "1234 Main St, Chicago, IL 60601".

Error #3: No actualizar Current Location

El error

Lunes estabas en Detroit, martes viajaste a Atlanta, pero la app sigue mostrando Detroit.

La realidad: El cálculo de deadhead queda completamente equivocado.

La solución: Cada vez que abres el calculator, verifica tu ubicación. Activa GPS auto-update en Settings.

Error #4: Olvidar tolls y fees en payment

El error

Broker: "$1,200 base + $60 tolls" → usuario ingresa: $1,200.

La realidad: Si el broker reembolsa tolls, eso es revenue adicional.

La solución: Suma TODO: Base $1,200 + FSC $150 + Tolls $60 + Detention $50 = $1,460 total.

Error #5: Confundir "Loaded Miles" con "Total Miles"

El error

Broker dice "800 millas" → usuario piensa "total" → ingresa en campo incorrecto.

La realidad: Los brokers casi siempre quotean solo loaded miles. El deadhead es tu responsabilidad.

La solución: 99% del tiempo, deja "Loaded Miles" en blanco. La app calculará el routing completo.

Error #6: No guardar loads rechazados

El error

Calculas load → malo → cierras app (no hay record).

La realidad: Lex AI no aprende, no tienes reference para loads similares futuros.

La solución: Siempre guarda en History, aunque sea DECLINE. Lex aprende tus preferencias.

Error #7: Usar CPM incorrecto o desactualizado

El error

CPM configurado hace 6 meses: $0.95/mi. Fuel subió, seguro aumentó → CPM real: $1.15/mi.

La realidad: La app muestra loads como "profitable" cuando NO lo son.

La solución: Revisa tu CPM mensualmente. Settings → Cost Per Mile → Update.

Checklist: antes de calcular cualquier load

Pre-calculation checklist
Current location está correcto (o actualizado)
Tengo dirección completa de pickup (no solo "Chicago")
Tengo dirección de delivery
Payment incluye TODO (base + FSC + tolls + fees)
Sé si delivery zone necesita repositioning
Mi CPM está actualizado (revisado este mes)
Entendí si broker dio "loaded" o "total" millas

Si todos ✓ → CALCULATE con confianza. Si alguno falta → consigue info primero.

La app te protege de olvidos.

Acción inmediata (5 minutos)

  1. Abre Settings en la app
  2. Verifica tu CPM actual
  3. ¿Cuándo fue la última vez que lo actualizaste? ______
  4. Si fue hace >30 días, recalcula usando Módulo 1
  5. Enable GPS auto-location si no está habilitado
  6. Revisa tus últimos 3 loads guardados: ¿Alguno tiene estos errores?

Garbage in = Garbage out.

La app es perfecta calculando... pero solo si le das data correcta. Evita estos errores → tus números serán 99% precisos.

Los 7 errores más comunes:

  1. Ignorar repositioning
  2. Direcciones vagas
  3. Current location desactualizado
  4. Olvidar tolls/fees en payment
  5. Confundir loaded vs total miles
  6. No guardar loads rechazados
  7. CPM desactualizado
